# balance-game

"평생 민초만 먹기 vs 평생 파인애플 피자만 먹기"

둘 중 하나를 골라 투표하고, 다른 사람들의 선택을 확인하는 밸런스 게임 사이트입니다.
Django 강의에서 배운 내용을 바탕으로 처음부터 직접 설계하고 배포합니다.

## 프로젝트 목표
- 강의를 따라 치지 않고 모델 설계부터 직접 해보기
- `ForeignKey`, 로그인, 권한, 테스트처럼 강의 노트에 없던 내용 익히기
- 처음부터 PostgreSQL로 개발하기
- 실제로 배포해서 친구들이 링크로 쓰게 만들기

## 만드는 기능

### 핵심 기능
- 회원가입, 로그인, 로그아웃
- 두 선택지가 있는 질문 등록
- 질문 목록과 상세 화면
- 1인 1표 투표
- 투표 후 선택지별 득표율 확인

### 추가 기능
- 내가 만든 질문 수정·삭제
- 댓글
- 인기순·최신순 정렬
- 랜덤으로 다음 질문 보기
- "내 선택은 소수파 12%" 같은 결과 문구

### 지금은 만들지 않는 것
- 소셜 로그인
- 실시간 결과 갱신
- 별도 프론트엔드 프레임워크, REST API
- 이미지 업로드

## 기술 스택
- Python 3.11
- Django 5.2
- PostgreSQL 17
- Django Template, CSS
- gunicorn, WhiteNoise (배포)

## 챕터별 계획

### 00. 프로젝트 준비
**목표:** Django가 로컬 PostgreSQL에 연결되고, 비밀값이 코드 밖으로 분리된 상태를 만든다.

- [ ] 가상환경을 만들고 패키지를 `requirements.txt`로 관리
- [ ] Django 프로젝트 생성
- [ ] PostgreSQL에 전용 유저와 데이터베이스 생성
- [ ] `SECRET_KEY`, DB 접속 정보를 `.env`로 분리
- [ ] `.env.example` 작성, `.gitignore` 설정
- [ ] 첫 `migrate` 전에 커스텀 유저 모델 설정

**완료 기준**
- `runserver`가 정상 실행된다.
- `psql`에서 Django가 만든 테이블이 보인다.
- `git status`에 `.env`가 나타나지 않는다.

> 커스텀 유저 모델은 첫 `migrate` 이후에 바꾸기 어려우므로, 지금 당장 추가할 필드가 없어도 먼저 만들어 둔다.

### 01. 회원가입과 로그인
**목표:** Django 인증 기능으로 회원가입부터 로그아웃까지 동작하게 한다.

- [ ] 회원가입 화면
- [ ] 로그인, 로그아웃
- [ ] 상단 메뉴에 로그인 상태 표시
- [ ] `login_required` 사용해 보기
- [ ] 인증 흐름 테스트 작성

**완료 기준**
- 비로그인 사용자가 보호된 페이지에 들어가면 로그인 화면으로 이동한다.
- 잘못된 비밀번호로는 로그인되지 않는다.

### 02. 질문 등록과 조회
**목표:** `Question` 모델을 직접 설계하고, 작성자와 `ForeignKey`로 연결한다.

- [ ] `Question` 모델 설계 후 리뷰받기
- [ ] Django Admin 등록
- [ ] `ModelForm`으로 질문 등록
- [ ] 질문 목록과 상세 화면
- [ ] 등록할 때 작성자를 서버에서 자동 저장
- [ ] 입력 검증과 뷰 테스트 작성

**완료 기준**
- 로그인한 사용자만 질문을 등록할 수 있다.
- 두 선택지가 같은 내용이면 등록되지 않는다.
- 없는 질문 주소로 들어가면 404가 나온다.

### 03. 투표와 결과
**목표:** 1인 1표를 애플리케이션과 DB 양쪽에서 보장하고, 결과를 집계한다.

- [ ] `Vote` 모델 설계 후 리뷰받기
- [ ] `UniqueConstraint`로 중복 투표 방지
- [ ] 투표는 POST 요청만 받기
- [ ] 동시 요청으로 생기는 `IntegrityError` 처리
- [ ] `annotate`, `Count`로 득표수 집계
- [ ] 투표한 사람에게만 득표율 공개
- [ ] 투표와 집계 테스트 작성

**완료 기준**
- 같은 사용자가 같은 질문에 두 번 투표할 수 없다.
- 존재하지 않는 선택지를 보내면 저장되지 않는다.
- 투표가 0개여도 오류가 나지 않는다.
- 득표율 합이 100%로 표시된다.

### 04. 첫 배포
**목표:** 핵심 기능이 동작하는 버전을 실제 URL에 올린다.

- [ ] 호스팅 서비스 선택 (요금과 PostgreSQL 보관 조건 확인)
- [ ] gunicorn 설정
- [ ] WhiteNoise로 정적 파일 서빙
- [ ] `DEBUG`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`를 환경변수로 관리
- [ ] 운영용 PostgreSQL 연결
- [ ] 배포 과정에 `migrate`, `collectstatic` 포함
- [ ] `python manage.py check --deploy` 경고 확인
- [ ] 배포 방법을 README에 정리

**완료 기준**
- 다른 기기에서 가입, 질문 등록, 투표, 결과 확인이 모두 된다.
- 배포 환경의 에러 화면에 디버그 정보가 나오지 않는다.
- 다시 배포해도 데이터가 사라지지 않는다.

### 05. 내 질문 관리와 권한
**목표:** "로그인했는가"와 "권한이 있는가"를 구분해서 처리한다.

- [ ] 내가 만든 질문 목록
- [ ] 질문 수정, 삭제
- [ ] 다른 사람의 질문 접근 시 403 또는 404 처리
- [ ] 투표가 시작된 질문의 수정 정책 정하기
- [ ] 권한 테스트 작성

**완료 기준**
- 주소나 요청을 직접 조작해도 남의 질문을 수정·삭제할 수 없다.
- 삭제는 POST 요청으로만 동작한다.

### 06. 댓글
**목표:** 여러 모델이 연결된 화면을 구현하고 쿼리 수를 관리한다.

- [ ] `Comment` 모델 설계 후 리뷰받기
- [ ] 댓글 작성, 삭제
- [ ] 투표한 사람에게만 댓글 작성 허용
- [ ] 댓글에 작성자의 선택 표시
- [ ] `select_related`로 N+1 쿼리 줄이기
- [ ] 댓글 권한 테스트 작성

**완료 기준**
- 다른 사람의 댓글은 삭제할 수 없다.
- 댓글 수가 늘어나도 페이지의 쿼리 수가 함께 늘지 않는다.

### 07. 재미 요소
**목표:** 친구에게 공유하고 싶어지는 기능을 붙인다.

- [ ] 인기순, 최신순 정렬
- [ ] 페이지네이션
- [ ] 아직 투표하지 않은 질문을 랜덤으로 보여주기
- [ ] 투표 후 소수파·다수파 문구 표시
- [ ] 링크 공유 시 보이는 제목과 설명 설정
- [ ] 모바일 화면 다듬기

**완료 기준**
- 질문을 전부 투표한 사용자에게도 빈 화면이나 오류가 나오지 않는다.
- 휴대폰에서 투표부터 결과 확인까지 불편하지 않다.

### 08. 마무리
**목표:** 실제 사용자의 반응을 받아 고치고, 프로젝트를 정리한다.

**완료 기준**

## 작업 규칙
- 모델은 코드를 쓰기 전에 필드와 관계부터 정리한다.
- 코드는 직접 작성하고, 막히면 공식 문서를 먼저 찾아본 뒤 질문한다.
- 기능을 추가할 때 테스트도 함께 작성한다.
- 04 챕터 이후에는 기능을 끝낼 때마다 배포한다.
- 막혔던 내용은 `notes/`에 정리한다.

## 커밋 규칙
`타입: 내용` 예: `feat: 질문 등록 폼 추가`

| 타입 | 용도 |
|------|------|
| `feat` | 새 기능 추가 |
| `fix` | 오류 수정 |
| `test` | 테스트 추가, 수정 |
| `docs` | README, 노트 수정 |
| `refactor` | 동작은 그대로, 코드 정리 |
| `chore` | 패키지, 설정, 배포 관련 작업 |
